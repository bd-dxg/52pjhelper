# 架构概述

52pjhelper 项目采用现代化的浏览器扩展架构，基于 WXT 框架构建，注重模块化、可维护性和开发体验。

## 架构设计原则

### 1. 模块化设计

- 功能独立，便于单独开发、测试和维护
- 清晰的模块边界和接口定义
- 低耦合，高内聚

### 2. 可组合性

- 使用 Vue 3 组合式 API
- 功能逻辑可复用和组合
- 统一的状态管理机制

### 3. 可测试性

- 单元测试覆盖核心逻辑
- 模拟浏览器环境进行测试
- 测试驱动开发

### 4. 可扩展性

- 易于添加新功能
- 配置驱动的功能管理
- 插件化架构设计

## 核心模块

### 1. Content Script 模块

负责在目标网页中注入功能逻辑。

**模块组成**：

- `index.ts` - 主入口，协调各模块
- `initialization.ts` - 功能初始化
- `messageHandler.ts` - 消息处理
- `storageListener.ts` - 存储监听

**设计特点**：

- 防止重复初始化
- 统一的消息路由
- 实时的状态同步

### 2. Popup 模块

提供用户设置界面。

**模块组成**：

- `SettingsPanel.vue` - 主设置面板
- 各种功能开关组件
- 配置管理界面

**设计特点**：

- 响应式布局
- 实时的配置同步
- 友好的用户交互

### 3. Background Script 模块

处理后台任务和事件。

**模块组成**：

- `versionChecker.ts` - 版本检查
- 定时任务管理
- 事件监听器

**设计特点**：

- 低资源占用
- 可靠的任务调度
- 错误恢复机制

### 4. 工具类模块

提供通用的基础设施。

**核心工具**：

- `storageHelper` - 存储操作封装
- `messageHelper` - 消息通信封装
- `urlMatcher` - URL 匹配工具
- `featureManager` - 功能管理基类

**设计特点**：

- 统一的 API 接口
- 错误处理和默认值
- 类型安全的操作

## 数据流架构

### 配置数据流

```
用户操作 → Popup组件 → browser.storage → Content Script → 页面效果
    ↑           ↓            ↑               ↓
    └─── 实时同步 ───┘       └─── 状态监听 ───┘
```

### 消息通信流

```
Popup组件 → messageHelper → browser.runtime → Content Script → 功能执行
    ↑           ↓                ↑                 ↓
    └─── 响应返回 ───────────────┘                 └─── 结果反馈 ───┘
```

### 状态管理流

```
本地存储 → storageHelper → 组件状态 → 用户界面 → 用户操作
    ↑           ↓             ↑           ↓
    └─── 变化监听 ────────────┘           └─── 状态更新 ───┘
```

## 性能考虑

### 1. 加载性能

- 按需加载功能模块
- 延迟初始化非关键功能
- 优化资源打包大小

### 2. 运行性能

- 使用事件委托减少监听器
- 避免不必要的 DOM 操作
- 使用 WeakSet 防止内存泄漏

### 3. 内存管理

- 及时清理事件监听器
- 使用弱引用避免循环引用
- 监控内存使用情况
